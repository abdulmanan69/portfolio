From the README

93 document, image, text and utility tools that run entirely in your browser. No uploads, no accounts, no tracking — and it keeps working with no connection at all.

ToolForge is a static single-page app. Once the page has loaded there is no server left to talk to: every merge, render, hash and conversion happens inside your browser tab using Canvas, Web Crypto, IndexedDB and a handful of well-known client-side libraries.

Privacy

The privacy claim is structural, not a promise: there is no backend to send anything to. The only network requests the app makes are for its own static assets, all of which are precached by the service worker on first load. You can verify this in DevTools -> Network, or by turning off Wi-Fi and using the app normally.

Local storage holds preferences, favourites and download history (file names and sizes, never contents). IndexedDB optionally caches recently opened files so you can re-run a tool without picking the file again; Settings -> Clear all local data removes everything.

Installation

Requires Node 20+.

git clone https://github.com/abdulmanan69/pdf-toolkit.git
cd pdf-toolkit
npm install

Local development

npm run dev        # start Vite on http://localhost:5173
npm test           # run the unit test suite
npm run typecheck  # strict TypeScript check
npm run build      # production build into dist/
npm run preview    # serve the production build locally
npm run icons      # regenerate the PWA PNG icons

predev and prebuild copy PDF.js's character maps and standard fonts into public/pdfjs/ so CJK documents render correctly offline. That folder is generated, and git-ignored.

GitHub Pages deployment

The repository ships with .github/workflows/deploy.yml, which type-checks, tests, builds and publishes on every push to main.

  1. Push the repository to GitHub.
  2. Go to Settings -> Pages and set Source to GitHub Actions.
  3. Push to main. The workflow builds and deploys automatically.

How the routing and SEO fit together

The site serves real URLs — /pdf-toolkit/tool/merge-pdf, not #/tool/merge-pdf — because hash fragments are invisible to crawlers. GitHub Pages has no rewrite rules, so the build does the work instead:

  1. prebuild regenerates public/sitemap.xml and public/robots.txt from src/tools/catalog.json, so the sitemap can never drift from the tool list.
  2. postbuild prerenders one real index.html per route (102 of them) into dist/, each with its own <title>, meta description, canonical URL, Open Graph tags and JSON-LD (SoftwareApplication + BreadcrumbList).
  3. A dist/404.html copy catches anything unmatched so the router still boots.

The result: every tool URL is a genuine 200 with unique metadata before a single line of JavaScript runs, and useSeo in src/seo.ts keeps those same tags correct during client-side navigation.

If you rename the repository, change base in vite.config.ts and SITE.url in src/seo.ts and SITE in scripts/seo.mjs — those three constants drive everything else.

How a tool is built

Adding a tool is usually about 30 lines. FileWorkbench owns the whole file loop — drag & drop, batching, progress, errors, per-file download and ZIP download — so a tool only describes its options and an async run:

export function GrayscaleImage() {
  const [amount, setAmount] = useState(100);
  return (
    <ImageTool
      toolName="Grayscale"
      actionLabel="Apply grayscale"
      ops={{ filters: { grayscale: amount } }}
      optionsKey={amount}
      options={<Slider label="Grayscale" value={amount} onChange={setAmount} min={0} max={100} />}
    />
  );
}

Then register it in src/tools/registry.ts with an id, icon, category and lazy import.

Known limits

Being honest about a browser-only design:

  • Very large files are bounded by device memory, not by an upload quota. Rasterising a 500-page scan is slower here than on a server.
  • Remove Watermark covers matching watermark text and deletes watermark/stamp annotations. Marks burned into a scanned image cannot be removed.
  • Convert to SVG embeds the raster in a scalable SVG container; it is not vector tracing.
  • Convert GIF exports the first frame — animation is not preserved.
  • Unlock PDF decrypts a document you already have the password for. It does not crack passwords.
  • OCR is marked Coming soon: a usable offline model is 10–15 MB per language, so it will ship as an opt-in download rather than bloating first load.

Contributing

  1. Fork and create a branch: git checkout -b feat/my-tool.
  2. Keep npm run typecheck and npm test green.
  3. Add unit tests for anything in src/lib/ — that layer is pure and fully testable.
  4. Match the existing conventions: tools live in a category module, get an entry in registry.ts, and reuse FileWorkbench/TextWorkbench instead of re-implementing uploads.
  5. Never add a network call. A pull request that sends user data anywhere will be declined.
  6. Open a PR describing the tool, the libraries it needs and its bundle impact.
